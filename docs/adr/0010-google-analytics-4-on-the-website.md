# 0010: the website counts visits with Google Analytics 4, and never sees a feed

- Status: accepted (2026-09-17)
- Date: 2026-09-17
- Relates to: the owner's 2026-09-17 decision to run Google Analytics 4 on every
  public portfolio site and update privacy pages and claims to match

## Context

The website at `chelseakr.github.io/tods-validate/` is the Pyodide playground
(`web/index.html`), the rule catalog (`web/rules/`, generated by
`scripts/generate_rules_doc.py`), and now a privacy page. Until this decision it
loaded nothing but Pyodide and the tods-validate wheel. Its promise to an agency
is that feed files never leave the browser, which is what makes it safe for
non-public operational data. `employee_run_dates.txt` carries employee
identifiers, so that promise is load-bearing.

The owner decided to run GA4 on every public site. The question here is how to
add page counts without weakening the feed promise.

## Decision

`web/analytics.js` is the only file that talks to Google. Every page loads it:
the playground and the privacy page with `<script src="analytics.js" defer>`, and
each rule page and the catalog with `<script src="../analytics.js" defer>` from
the generator. It holds the measurement ID `G-TM683Q87RD` (GA4 property
554837399, 14-month retention, Google signals disabled). Setting it to `""`
removes GA and the opt-out control.

With an ID set, it loads `gtag.js` only when all of these hold:

- the page is served over HTTPS from `chelseakr.github.io` under
  `/tods-validate/`, so local previews, the pa11y and boot-check servers on
  127.0.0.1, and CI never contact Google;
- `navigator.globalPrivacyControl` is not `true`, and Do Not Track
  (`navigator.doNotTrack`, `window.doNotTrack`, `navigator.msDoNotTrack`) is not
  `"1"` or `"yes"`; and
- the visitor has not opted out (localStorage `tods-validate:analytics-opt-out`
  is not `"1"`).

When it loads, it sets Consent Mode v2 defaults (the three ad signals denied
everywhere; `analytics_storage` denied through `region` for the EEA, GB and CH,
granted elsewhere), and configures GA with `allow_google_signals: false`,
`allow_ad_personalization_signals: false`, `page_location` set to origin plus
path, and `page_referrer` set to the referring origin. It never reads the file
input, the Pyodide filesystem, or the report iframe, and it sends no custom
events.

Each page's footer carries an "Opt out of analytics" / "Opt back in" button
that `analytics.js` wires. It stores the flag, sets Google's
`window["ga-disable-G-TM683Q87RD"]`, and explains itself under GPC/DNT or when
storage is blocked.

The playground's CSP gains the minimum GA origins:
`https://www.googletagmanager.com` in `script-src`;
`https://*.google-analytics.com https://*.analytics.google.com
https://www.googletagmanager.com` in `connect-src`; and
`https://*.google-analytics.com https://www.googletagmanager.com` in `img-src`.
The privacy page carries its own CSP with the same GA origins. The rule pages
have no CSP and gain none.

## Consequences

- The website is no longer third-party-free. The feed promise is unchanged, and
  the playground lede now says so next to the GA sentence. `web/README.md`,
  the README, `docs/data/user-supplied-feeds.md` and the DPIA-lite in
  `docs/RESPONSIBLE-TECH-AUDITS.md` are updated to say exactly that.
- The CLI, Action, pre-commit hook, Docker image, LSP and editor extension are
  untouched. None of them loads `analytics.js`.
- `tests/test_analytics.py` runs the loader in Node for each guard, with
  negative controls that remove a guard and assert the harness notices. The
  rule-page tests pin the one allowed script.
- Owner steps in the GA4 web stream: under Enhanced measurement, turn off
  "Page changes based on browser history events", "Site search" and "Form
  interactions". The playground has no `<form>`, but the setting should match
  the other sites.
