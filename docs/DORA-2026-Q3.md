# Delivery health review: 2026 Q3

Last verified: 2026-08-27
Recheck cadence: quarterly, next due 2026-11-30

This is the QM-11 review from `docs/standards/QUALITY-AND-METRICS-STANDARD.md`
("a portfolio-level health signal, not a per-PR gate, reviewed quarterly"),
run together with the quarterly review that
`docs/standards/AI-DEVELOPMENT-MEASUREMENT-STANDARD.md` asks for, because that
standard's own cadence line says the two run together. Numbers are mined from
`git` and `gh` by `scripts/delivery_metrics.py`; the machine-readable snapshot
is [`DORA-2026-Q3.json`](DORA-2026-Q3.json).

Two things this review will not do. It will not fabricate a zero for a metric
it cannot measure, which is the failure mode the standard names explicitly.
And it will not end without an action, which is the anti-pattern the AI
standard names: "every quarterly review must produce at least one action or an
explicit 'no action, because...'".

## Why this repository's shape changes what is measurable

`tods-validate` is a library and CLI, not a hosted service. The standard says
so directly: "library/CLI repositories report DF/LT only". There is no
deployment to fail and no service to restore, so two of the five metrics are
**N/A with a stated trigger**, not zero.

The one deployed surface is the GitHub Pages playground, and it is where the
only real delivery failures in this repository's history have happened. Those
are counted below rather than excluded on a technicality.

| Change lead time (commit to prod) | p90 under 1 day | **p50 2.8h, p90 131h** over 118 merged pull requests | **Breached at p90** |

### The two failed releases

Both are documented in `CHANGELOG.md` and neither needed inventing:

- **v0.9.1** was tagged and signed but its GitHub Release object was never
  created, so `pypi-publish.yml` never ran. PyPI stayed at 0.9.0 while the
  playground pinned `tods-validate==0.9.1`, so the deployed page could not boot
  for any visitor. Detected 2026-08-21 (#136), resolved by v0.10.0 on
  2026-08-22. **Recovery time: 5 days**, and the clock only started when
  somebody noticed; no gate was watching, which is itself the finding.
- **v0.10.0** permanently tags a `web/index.html` still pinned to `0.9.0`,
  because the repin (#142) landed after the tag. A tag cannot be corrected in
  place.

Recovery time is reported for the first only. The second was never restored,
because it cannot be: that is a different kind of number and averaging it in
would hide the difference.

### Failed-deployment recovery time is a sample of one

The standard makes this metric N/A until the incident-label convention is
adopted. It was adopted on 2026-08-27, in the same change as this review, and
no incident issue exists yet. The five days above is reconstructed from the
changelog and the tag dates, and is recorded as a **backfill**, not as a
measurement. From the next incident onward it comes from issue open and close
timestamps, per IR-03.

### Lead time's p90 needs reading, not just quoting

p50 is 2.8 hours and p90 is 131 hours. That spread is not a queue: it is a
solo maintainer opening a pull request, leaving it while something else takes
priority, and coming back. The floor exists to catch review queues, and this
repository has no reviewer to queue behind, which is the same structural fact
CODEOWNERS records. **It is reported as breached anyway**, because writing an
exemption for the one metric that looks bad is how a ledger stops being worth
reading.

## AI-development measurement

`AI-DEV-MEASUREMENT: APPLIES`. Recorded in the metrics ledger of
`docs/roadmap.md` per the standard's section 8.

The standard's rule is that diagnostic signals are tracked and never gated on,
and that every throughput metric ships with a quality-debt counterweight. The
counterweights, measured on `origin/main`:

| Counterweight | Definition | Measured | State |
| --- | --- | --- | --- |
| Revert rate | revert commits / merges | **0 / 160 commits** | BASELINE, graduation decision **2026-11-30** |
| Unreviewed-merge rate | pull requests merged with zero review | **113 of 118, 96%** | BASELINE, graduation decision **2026-11-30** |
| Short-term churn (14d) | share of edits re-touching code under 14 days old | not yet collected | BASELINE, graduation decision **2026-11-30** |
| AI-authored share | commits carrying a `Co-Authored-By: Claude` trailer | **32 of 160, 20%** | Diagnostic. Never gates. |

Every BASELINE row above carries a dated graduation decision, because the
standard is explicit that "a BASELINE row without a graduation date is a
conformance failure, same as an aspirational row". On 2026-11-30 each either
becomes a gate or is retired.

The 96% unreviewed-merge rate is the honest headline of this review. It is not
a process failure to be fixed by a policy; it is one person with no second
maintainer, the same fact `.github/CODEOWNERS` already records in its own
comment. What the branch ruleset in `docs/rulesets/main.json` changes when it
is applied is that the number stops being invisible: with
`require_code_owner_review` on and `bypass_actors` empty, every merge without a
review becomes an explicit, recorded bypass rather than the default.

## Actions

The standard requires at least one action or an explicit "no action, because".

1. **Deployment frequency is at the floor with no margin, and the last release
   was 2026-08-22.** The 14-day alert fires on 2026-09-05. Either a release
   ships before then or the next review records why not.
2. **Change fail rate is 20%, and both failures were the same defect class**: a
   released artifact and the thing it points at disagreeing. Two gates now
   exist that would have caught them (`tests/test_playground.py`'s pin check,
   and `scripts/check-playground-boots.cjs`). No further action; the next
   review re-measures against them.
3. **Recovery time has a sample of one and a backfilled one at that.** The
   action is the incident-label convention adopted alongside this review; the
   metric becomes real at the next incident.
4. **Rework rate is not measurable.** No action: with zero reverts in 160
   commits there is nothing to compute a ratio from, and the honest report is
   N/A rather than 0%. The trigger that retires the N/A is the first revert.
5. **Unreviewed-merge rate, 96%.** No action available in this repository: it
   is gated on a second maintainer, which phase 4 of
   `docs/MULTIYEAR-PLAN.md` records as a person rather than a milestone.
   Applying the branch ruleset makes each instance recorded rather than
   default, which is the only improvement available without one.

## Method

`python scripts/delivery_metrics.py --quarter 2026-Q3` regenerates the JSON
snapshot beside this file. It reads merged pull requests and published releases
through `gh`, and commits through `git`; it computes nothing it cannot source,
and writes `null` with a `reason` rather than `0` for anything it cannot
measure. `tests/test_delivery_metrics.py` pins that last part, because a
collector that reports zero for "no data" is the same defect as a gate that
passes when it did not run.
